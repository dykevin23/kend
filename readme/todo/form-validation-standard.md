## 배경

현재 앱에는 **폼 입력 검증(validation)의 통일된 표준이 없다.** 두 메커니즘이 혼용된다:

1. **클라이언트 1차**: 입력에 `required` 속성 → 빈 값 제출 시 **브라우저 네이티브 검증 버블**("이 입력란을 작성하세요")
   - 사용처: `join-page`, `find-password-page`, `reset-password-page`, `submit-child-page`, `edit-child-page` 등
   - ⚠️ 이 버블은 **브라우저 기본 동작**이라 스타일/문구를 우리가 못 바꾼다 (브라우저·OS·로케일마다 다름)
2. **서버 2차**: action 에서 **zod** 검증 → 실패 시 **빨간 에러 박스**(우리 디자인)로 표시
   - 사용처: 9개 페이지에서 `safeParse`/`z.object`

→ 결과적으로 **빈 값은 네이티브 버블, 그 외(형식/서버)는 빨간 박스**로 스타일이 갈린다. 커스텀 클라이언트 검증(react-hook-form 등)은 도입돼 있지 않다.

---

## 선택지

| 안 | 내용 | 장단 |
|----|------|------|
| **A. 현행 유지** | `required`(네이티브) + 서버 zod(빨간 박스) | 공수 0, 즉시 피드백 / 버블 스타일 불일치(변경 불가) |
| **B. 빨간 박스로 통일** | `required` 제거 → 빈 값도 서버 zod 빨간 박스로 처리 (또는 가벼운 클라 체크 후 동일 컴포넌트) | 스타일 일관 / 빈값도 서버 왕복, 즉시성 저하 |
| **C. 커스텀 클라 검증 도입** | react-hook-form + zod resolver 등으로 인라인 검증 통일 | 가장 일관·UX 우수 / 공수 큼, 의존성 추가 |

---

## 권장

- **출시 전**: A(현행 유지)로 충분. 기능 동작엔 문제 없음.
- **일관성을 원하면**: B (가벼움). 네이티브 버블 스타일은 못 바꾸므로 "일관성"이 목표면 `required`를 걷어내고 빨간 박스로 모아야 함.
- **폼이 많아지고 UX 욕심나면(출시 후)**: C.
